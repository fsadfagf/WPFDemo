- ViewCustomerInfo / ViewAddressInfo 当前**还没有任何 ViewModel 或 Repository 真正查询 V_CustomerInfo / V_AddressInfo 视图**（仓库里写好了重载但没人调用）。下次接视图查询前要再复核：
  - 基类 `SexName` / `StatusName` 是 `[SugarColumn(IsIgnore = true)]` 的计算属性，派生类加了 `new` 字段后，SqlSugar 反射时**两套同名属性**都会被扫到列映射，可能出现"基类的计算属性被映射出列"的隐患。如果接视图后真遇到列重复，建议把基类那两个计算属性挪到 View 子类，或者基类直接 `protected` / 改名。

## 完成 AddressList + UserList 两个列表页

用户说"完成 Addlist 界面"，确认后两个都做了（AddressList 地址列表 + UserList 用户列表），照 CustomerList 的既有套路对齐。

### 新增文件（8 个）
- `ViewModel/AddressListViewModel.cs` / `ViewModel/UserListViewModel.cs`：查询条件 + 分页 + AddEdit/Enable/Delete 命令
- `ViewModel/AddandEditAddressViewModel.cs` / `ViewModel/AddandEditUserViewModel.cs`：弹窗 VM
- `View/Pages/AddandUpdateAddressWindow.xaml(.cs)` / `View/Pages/AddandUpdateUserWindow.xaml(.cs)`：弹窗
- `View/Pages/AddressList.xaml(.cs)` 与 `UserList.xaml(.cs)` 从空壳改成完整页面（已登记 csproj）

### 关键改动
- **`AddressRepository` 扩成完整 `IRepository<AddressInfo>`**（原来只有 `GetAll()`）：加了 Add/Update/Delete/GetList/GetListByPage，`Delete` 是逻辑删除（Status 置 1）。`GetAll()` 保留给客户下拉框用。
- **`AddressInfo` / `UserInfo` 各加 `StatusName` 计算属性**（`[SugarColumn(IsIgnore = true)]`，Status==0?"正常":"禁用"），供列表"状态"列显示，与 CustomerInfo 保持一致。
  - ⚠️ 加了之后跟 `ViewAddressInfo.StatusName` / `ViewUserInfo.StatusName` 撞名，顺手给这两个也加了 `new`（跟昨天处理的同一类问题）。**记住：以后给基类加属性，要同步检查三个 View* 子类有没有同名属性。**
- **`UserInfo.UserId` 补了 `[SugarColumn(IsPrimaryKey = true, IsIdentity = true)]`** —— 原来完全没有主键标记！SqlSugar 默认只认 `Id`/`ID`，不标记会导致 `Updateable(model)` 找不到主键、`InSingle(id)` 失效。这是启用/删除/修改功能的隐藏地雷，已修。
- **UserList 整表 `IsReadOnly="True"`，没有 SaveRow**：密码不在列表里显示，改资料一律走弹窗。密码框用项目已有的 `PasswordBoxHelper`（命名空间 `手写MVVM.Helper`，XAML 里 `xmlns:helper="clr-namespace:手写MVVM.Helper"`，用法 `helper:PasswordBoxHelper.Attach="True"` + `helper:PasswordBoxHelper.Password="{Binding ...}"`）。
- **AddressList 支持单元格双击直接改**（省份/城市/区域/详细地址），`CellEditEnding` 里先 `GetBindingExpression().UpdateSource()` 再调 `SaveRow`，Esc 取消时不保存 —— 与 CustomerList 同款。
